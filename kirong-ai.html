The problem

A useful AI product needs more than a chat box. It needs persistent state, tools, controlled execution, recovery from failure, human approval for anything risky, and a clear boundary between what the model decides and what the server actually authorizes. Most chat-wrapper products skip all of this.

The solution

I built a custom application-level agent engine around a strict Plan → Act → Observe loop. The planner proposes one JSON action at a time. The server classifies that action's risk, applies permission rules, executes only approved tools, records the observation, and persists a checkpoint before continuing to the next step. Nothing the model "decides" runs unless the server independently agrees it's safe to run.

Engineering layers

AI RouterRoutes agent planning and chat work across configured providers including OpenAI, Groq, Cerebras, OpenRouter and Gemini support — so the system stays responsive even if one provider slows down.
Data LayerPrivate Vercel Blob storage for chats, memory, projects, files, research, agent runs and audit records, partitioned by device/workspace context.
Agent RuntimeOne action per planning step, real tool observations, bounded step budgets, checkpoint persistence, and resumable runs after interruption.
ExecutionVercel Sandbox provides isolated Firecracker-based execution for allowed code workflows; numeric calculations use a separate bounded evaluator.
SafetyEvery proposed action is reclassified server-side. Non-low-risk actions require explicit human approval, with every decision recorded in an audit trail.
KnowledgeUploaded PDF/DOCX/text sources are extracted and made available to the agent, using bounded text/keyword retrieval rather than a vector database.

Key features

  • Custom Plan → Act → Observe agent loop
  • Multi-provider AI routing with fallback providers
