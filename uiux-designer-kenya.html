I'm Kirong Job Kwemoi, a UI/UX Designer based in Nairobi. Before a line of code gets written, I map out who's using a product, what they're trying to do, and where they'd naturally get stuck — so the interface feels obvious instead of explained.

My approach

Design that looks good but confuses the first-time user has failed at its actual job. I design for clarity first — a visitor should know within seconds what a page is for and what to do next. That means restraint: fewer competing elements, a clear visual hierarchy, and interactions that behave the way people already expect them to.

Since I also build the software myself, design decisions stay grounded in what's actually feasible to implement well — not a beautiful mockup that becomes a compromise once development starts.

How a design project runs

01

Understand the users and goal

Who's using this, what are they trying to accomplish, and what does success look like for the business.

02

Map the flow

The path someone takes from arriving to completing their goal — booking, ordering, signing up — before any visual design happens.

03

Design the interface

Layout, typography, and visual system — built to be purposeful, not decorative for its own sake.

04

Build it properly

Since I build the software too, the design translates into the real product without losing fidelity along the way.

Where this shows up

Every site and system I build carries this thinking — from the booking flow on Nyeri Runners Fit to the checkout experience on Malaika Beauty Salon, down to the interaction design inside Kirong AI itself.
